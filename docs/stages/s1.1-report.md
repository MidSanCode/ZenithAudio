## 3. 实时安全

`render_block` 路径逐项核对（ABI P5）：

- **无堆分配**：source / output / chain_planar / sum_scratch / order_scratch 均在
  `Engine::new` 预分配；`process_mixer` 用 `order_scratch` 而非 `order().to_vec()`。
- **无锁**：状态经 `EngineSnapshot`（原子字段）发布，Dart 无锁读。
- **无 IO / 无打印**：音频路径无 `println!`。
- **无 panic 跨 FFI**：所有 `extern "C"` 经 `guard()`。

> 说明：`zenith_engine_render` 的**单声道**分支会分配一个临时 `Vec`。该函数是
> 控制线程/测试用的拉取入口，不是设备回调路径；设备回调（`cpal`）直接调用
> `Engine::render_block`，走立体声零分配路径。此取舍写在函数文档中。

## 4. 未启用真实设备驱动（重要，如实记录）

`cpal` 是**可选外部 crate 依赖**。本机处于**离线环境**，且用户明确要求
**不得安装软件包、不得污染系统环境**，因此：

- 默认构建**不包含** `cpal`，`Cargo.toml` 里以注释给出启用方式；
- `driver/cpal_driver.rs` 仅作 `cfg(feature = "cpal")` 门控骨架；
- `zenith_engine_start` 在无设备驱动时返回 `ZENITH_ERR_UNSUPPORTED`，**不假装成功**；
- 因此 `lib/engine/audio_engine_adapter.dart` 的 provider **仍委托旧 `AudioService`**，
  未切换到 `FfiAudioEngine`——在没有设备驱动时切换会让应用静音，违反「不得破坏
  现有行为」。`FfiAudioEngine` 已完整实现并通过冒烟测试，一旦 `cpal` 可用即可
  改一行 provider 切换。
